## Objetivos

Al terminar esta página podrás:

- Cargar un dataset del Hub por sus ficheros cuando el atajo por nombre no funciona.
- Transformarlo con `map`, `filter` y `cast_column`, y partirlo manteniendo la proporción de cada clase.
- Leer un dataset grande en streaming, sin descargarlo entero.
- Subir un dataset propio a tu cuenta, privado, con su ficha, y cargar una versión concreta.

## Teoría

### Qué resuelve la librería `datasets`

Los datos de las prácticas anteriores eran ficheros JSONL que el curso leía a mano. Funciona con 30 tickets, pero en un proyecto real los datos son grandes, cambian y los comparten varios equipos. `datasets` resuelve tres cosas:

- **Cargar** de muchos sitios (el Hub, ficheros locales, S3) en el mismo formato, con tipos declarados (*features*).
- **Procesar** sin cargar todo en memoria: guarda los datos en Arrow, un formato en columnas en disco, y cada transformación se cachea.
- **Versionar y compartir**: un dataset del Hub es un repositorio con historial, así que puedes fijar la versión exacta con la que evaluaste.

Si vienes de backend: es como pasar de leer CSV con un bucle a tener una tabla con esquema, consultas y migraciones versionadas.

### Datasets con script: ya no

Hasta hace unas versiones, un dataset del Hub podía traer un script de Python que lo descargaba y lo preparaba. `datasets` lo ejecutaba al cargar. Era cómodo y era un riesgo: cargar un dataset ejecutaba código de un tercero. Las versiones actuales ya no ejecutan esos scripts. Muchos datasets antiguos siguen teniéndolos, y para usarlos hay que cargar sus ficheros directamente (la anatomía).

### Tipos que importan

Una columna de etiquetas puede ser texto (`"0"`), un entero (`0`) o una `ClassLabel`: un entero con nombre (`0 = negative`). La última es la que deja hacer cosas útiles, como partir en train y test manteniendo la proporción de cada clase (estratificar). Con tres clases equilibradas, una partición al azar puede dejar el test desequilibrado, sobre todo con pocos datos.

## Práctica

[`datasets_practica.py`](https://github.com/alejbrata/dev_to_ia_engineer/blob/main/modulos/b-hugging-face/datasets_practica.py) trabaja con los tuits en español de la B.3 y con los tickets del módulo 2. Lo esencial:

```python
from datasets import ClassLabel, load_dataset

base = "hf://datasets/cardiffnlp/tweet_sentiment_multilingual/data/spanish/"
ds = load_dataset("json", data_files=f"{base}train.jsonl", split="train")
ds = ds.map(lambda f: {"label": int(f["label"])})                    # "0" → 0
ds = ds.cast_column("label", ClassLabel(names=["negative", "neutral", "positive"]))
partes = ds.train_test_split(test_size=0.2, seed=0, stratify_by_column="label")

flujo = load_dataset("json", data_files=f"{base}test.jsonl", split="train", streaming=True)
primeras = list(flujo.take(3))                                        # sin descargar todo
```

## Mide y depura

### Mira los tipos al cargar

La parte 1 enseña que la etiqueta llega como texto (`Value('string')`), no como número ni como clase. Si la comparas con un entero, `"0" == 0` es `False` en Python y el acierto sale cero sin ningún error. Por eso el laboratorio de la B.3 convierte a nombres de clase al cargar (`datos.py`), y esta práctica la convierte en `ClassLabel`. Mira `features` cada vez que cargues un dataset nuevo.

### Comprueba la partición

Tras partir estratificando, el test queda con 123, 123 y 122 de cada clase: la misma proporción que el original. Mide siempre la distribución de clases de cada partición. Un test desequilibrado cambia lo que significa el acierto: con el 60 % de una clase, un clasificador que siempre dice esa clase acierta el 60 %.

### Fija la versión con la que evaluaste

El dataset que subes tiene historial, como un repo de código. Leer con `revision=` devuelve los datos exactamente como estaban en ese commit, aunque después alguien los cambie. Es lo que hace reproducible una eval del módulo 4 con datos compartidos: guarda junto a los resultados el commit del dataset, igual que la huella de `evaluar.py`.

### Streaming para mirar antes de descargar

Con `streaming=True`, `take(3)` lee las tres primeras filas sin descargar el resto. Con 870 tuits no importa, pero con datasets de cientos de gigas es la forma de ver qué hay dentro antes de decidir si te sirve.

## Errores frecuentes

**Cargar por nombre un dataset con script.** Las versiones actuales no lo ejecutan. Carga sus ficheros con `hf://` (la anatomía).

**No mirar los tipos.** Una etiqueta en texto, comparada con números, da cero aciertos sin avisar.

**Partir sin estratificar con pocos datos.** El test puede quedar desequilibrado. Usa `stratify_by_column` con una `ClassLabel`.

**Evaluar contra "la última versión" de un dataset compartido.** Si cambia, tus cifras dejan de ser comparables. Fija la revisión.

**Subir datos sin ficha o sin revisar qué contienen.** Una ficha dice qué es, de dónde sale y con qué licencia se puede usar. Y repasa que no haya datos personales antes de subir nada, aunque sea privado.

### Anatomía de un error: el dataset que ya no se puede cargar por su nombre

El primer intento de cargar los tuits, como dicen muchos tutoriales:

```text
load_dataset("cardiffnlp/tweet_sentiment_multilingual", "spanish")

RuntimeError: Dataset scripts are no longer supported, but found tweet_sentiment_multilingual.py
```

**Cómo leerlo.** El error dice qué encontró: un fichero `.py` en el repo. No dice que el dataset no exista ni que no tengas acceso, así que los datos están ahí.

**Causa.** El repo trae un script de carga de la época en que `datasets` los ejecutaba. Las versiones actuales dejaron de hacerlo, porque ejecutar código al cargar datos es un riesgo de seguridad.

**Solución.** Mirar qué ficheros tiene el repo (en la web o con `HfApi().dataset_info(...).siblings`) y cargarlos directamente:

```python
load_dataset("json", data_files="hf://datasets/cardiffnlp/tweet_sentiment_multilingual/data/spanish/test.jsonl")
```

Muchos repos antiguos tienen además una conversión a Parquet que hace el Hub; si existe, también sirve. Y si eres tú quien publica, sube los datos en ficheros (Parquet o JSONL) y nunca un script, como hace `push_to_hub`.
